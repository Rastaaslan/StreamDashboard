# F10 — sauvegarde et restauration d'une copie temporaire QA sur FIXE

## Périmètre exécuté
- Source : branche canonique `streamcockpit/3.0-full-experience`, FIXE Windows 11 uniquement. Une nouvelle fonction de sauvegarde et restauration **QA uniquement** a été ajoutée dans `apps/desktop/src/streamcockpit-upgrade-qa-checkpoint.ts`. Elle n'est pas raccordée au mécanisme Squirrel, ne s'applique **jamais** à RC2, aux profils utilisateurs ou aux installations ; aucun processus externe n'est lancé.
- Seuls les dossiers **directement sous le TEMP Windows**, nommés `sc3-upgrade-qa-*`, sont acceptés. La source de test est `active/`; une sauvegarde immuable `backup/files/` est publiée uniquement après vérification des empreintes SHA-256 et double lecture du contenu de la source. La taille et le nombre de fichiers sont bornés ; liens symboliques/reparse points apparents et fichiers non réguliers refusés.
- Le manifeste mémorise chemins relatifs, tailles et SHA-256 mais jamais les données de profil ou des secrets. La restauration crée exclusivement un dossier **neuf** `restored/` dans le même espace temporaire ; elle refuse une sauvegarde modifiée, les chemins non valides et tout écrasement. Les données binaires synthétiques de type SQLite et les données de configuration chiffrées synthétiques sont comparées octet par octet après restauration.
- Réserve : la validation d'un `file.sync()` et du renommage sur Windows ne constitue **pas** la qualification d'une durabilité disque lors d'une coupure électrique ; aucun verrou de plusieurs processus, intégration Squirrel, signature de production, profil réel, compatibilité Android ni rollback matériel n'est revendiqué.
