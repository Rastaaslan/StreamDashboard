# F05 — pistes OBS et monitoring lus à la demande (FIXE, 2026-11-03)

## Intégration
- Nouveau parcours **lecture seule** du panneau mixeur : sélectionner une source, cliquer « Lire les pistes OBS ». Aucun polling supplémentaire ni commande `SetInputAudioTracks`, aucun changement de monitoring.
- Le client OBS FIXE observe les six booléens de pistes via `GetInputAudioTracks`, et le mode `GetInputAudioMonitorType`, avec double lecture `GetInputList` et contrôle UUID de source + génération OBS. Une source renumérotée, disparue, hors ligne ou donnée mal formée donne une erreur ; aucun ancien état positif n'est conservé.
- `GET /api/v1/streamcockpit-mixer/routing?sourceId=...` : permis uniquement aux appareils appairés avec droit `observe` et au rôle hôte Windows OBS-executor. Autorisation recontrôlée après les lectures asynchrones OBS, pas de fuite d'UUID de source ni des secrets dans la réponse ; toute réponse est `private, no-store`. HEAD/POST/PUT refusés.
- Interface Android/Desktop : lecture uniquement après clic, valeurs rendues en `textContent`, source et autorité perdues = affichage révoqué. Écran tactile 320 px vérifié. Les pistes 1–6 représentent la configuration d'OBS, **pas** une preuve de l'identité de piste Twitch VOD ni de séparation Spotify, ni du câble audio du PC jeu. Le VOD global reste `unverified`.
