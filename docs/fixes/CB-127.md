# CB-127 — mobile series action detached during refresh

Base: `413b9b6d43e59dc8982bd38a53e0688a73322ca1`.

## Cause and correction

`renderPlanning` unconditionally called `replaceChildren` on every render. HTTP
state refreshes (including the 10-second health check), WebSocket `state.updated`
and offline/provider state renders all reach this function. Opening native
`details` only changes DOM state; rebuilding its row discarded that state, focus,
and the button between pointer down and click. Companion synchronization updates
its cache/sync center; any subsequent planning render had the same destructive
behavior. Row handlers themselves were not duplicated: their nodes were replaced.

Retain rows by event/series ID plus occurrence key while their complete item data,
connection mode and native provider availability are unchanged. Reconcile the
visible page without detaching retained rows. Changed items get new handlers and
fresh data; removed/filtered rows leave the cache. Filtering, temporal selection
and pagination still run on every render. No polling is suspended, no timeout is
changed, and no sleep or click retry is introduced.

The regression test fails on the base after an HTTP heartbeat with an expanded
menu. It checks node identity and focus, delivers a WebSocket update changing a
neighboring event between pointer down/up, verifies that the editor opens, then
updates the series and verifies fresh editor data. The existing round-trip test
continues to cover timezone, recurrence exceptions and occurrence description.

## Validation

Executed on Linux with Chromium (Windows CI itself is not available locally).
Playwright's temporary files and downloaded browser use workspace-local `.tmp`
via `TMPDIR` and `PLAYWRIGHT_BROWSERS_PATH` because the default paths are restricted
or empty. `npm test` also needs that browser path for its Node browser tests.

The standalone planning handler test's DOM facade now models `insertBefore`,
`remove` and parent links, and loads the row-cache initialization along with the
renderer. This keeps its real provider-sync lifecycle checks applicable.

- Before fix: `npm run test:browser -- --grep CB-127` failed on lost focus/menu
  after the heartbeat, reproducing the destructive render.
- `npm run test:browser -- --grep 'CB-127|CB-52 mobile series round trip' --repeat-each=5`:
  10 passed.
- `npm run test:browser -- --repeat-each=3`: 42 passed.
- Final browser regression (including explicit heartbeat completion assertion):
  `npm run test:browser -- --repeat-each=5`: 70 passed.
- `node --test tests/cb2-local.test.mjs`: 7 passed.
- `npm run build` and `git diff --check`: passed.

An initial full run lacked the browser path and was stopped after Node browser
launch failures. Another run alongside browser repetitions hit an unrelated
5-second CB-122 recurrence test timeout (that test passed in isolated full runs).
Neither test timeouts nor retries were changed. The subsequent full run exposed
the standalone test facade incompatibility described above, which was corrected.

Final `PLAYWRIGHT_BROWSERS_PATH="$PWD/.tmp/browsers" npm test`: passed,
121 Vitest files / 1,021 tests plus 160 Node tests, no failures or skips.
